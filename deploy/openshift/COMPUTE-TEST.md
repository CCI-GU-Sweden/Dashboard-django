# Compute module: test deployment

Deployed 2026-11-23 to `core-omero-test` for evaluation. Core commit `78c077179e4d7a7b186364775c38efc12b9faa6f` pins compute commit `860e2bf86755914022a08b2ad9b4b8e4cb64f643`; dashboard and collector use image digest `sha256:a0f32033bacc7cdcd91ebda349cc7fa33c5e0f3be5ea87b276493bf405668564`. The preceding dashboard image was `sha256:e009c0626783dc2113f7b23be224136ced328528e0e8f35de0a1d30b2dd62d77`. `DASHBOARD_COMPUTE_ENABLED=1` enables the page. The `dashboard-compute-collector` CronJob runs each minute under a dedicated service account with namespace-scoped pod and pod-metrics list access. It filters direct Job owners beginning `metrology-processor-`; no changes were made to the processor.

The compute migrations were tested on isolated PostgreSQL 15 database `dashboard_compute_validation_20261123`, then applied to `omerofilestats`. The dashboard role `filestats_dashboard` received SELECT/INSERT on snapshots and usage, SELECT on rates and sequence access for inserts. `dashboard_backup_reader` received SELECT on the three tables and sequences. Pre- and post-migration custom-format database backups were saved locally under `backups/`; ensure normal scheduled backups can read the new tables. The isolated database and validation Jobs remain for follow-up cleanup.

The one-off collector Job and a scheduled run completed with no active metrology pod, so end-to-end collection of a real processor run remains to be verified. Rates are unset. Reported resource usage integrates only the Metrics API windows and omits the gaps between them: this is incomplete and unsuitable for billing. Group labels are unverified; unlabeled jobs use CCI. Disk is nullable and currently unmeasured. CSV import and retention/rollup are not implemented. Review all of these before production or invoicing.

To stop test collection, suspend the CronJob. To hide the feature, set `DASHBOARD_COMPUTE_ENABLED=0`; neither action deletes data. If rolling back the dashboard image, disable the feature before returning to a version without the module. Do not delete or restore the shared database as a routine rollback. The test collector manifest was created specifically for this environment; adapt the module's example manifests and database privileges for any future deployment.
